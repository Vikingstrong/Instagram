## Решения (P-17, соло)

- Дарит любой, кто может смотреть эфир (политика постов автора), пока эфир
  `LIVE`. Ведущий себе не дарит (`409 LIVE_STATE_CONFLICT`).
- Клиент передаёт только `{ id, giftKey }`. Цену берёт сервер из каталога,
  получателя — из записи эфира. Автор получает полную цену.
- Отмены и возвраты нет: подарок окончателен.
- Гонка с завершением: транзакция подарка сначала блокирует строку эфира
  (`SELECT … FOR UPDATE`), завершение эфира обновляет ту же строку. Подарок
  либо принят, пока эфир `LIVE`, либо отклонён `409 LIVE_ENDED` без списания.
- Повтор с тем же `id` возвращает тот же подарок, в том числе после конца
  эфира; другой подарок с тем же `id` — `409 COINS_OPERATION_CONFLICT`.
- Лимит — 30 подарков в минуту на пользователя.

## Хранение и API

- `live_gifts` (миграция `20261025030000_live_gifts`): `id` — это id
  операции `coin_operations` (FK), эфир, отправитель, ключ подарка, цена и
  ключ повтора (unique с отправителем). Записывается в той же транзакции,
  что `CoinsService.transferGift`. Эфиры с подарками не удаляются очисткой
  завершённых эфиров: они — контекст переводов.
- `POST /api/v1/lives/{id}/gifts { id, giftKey }` → 201
  `{ gift, balance }` (`balance` — кошелёк отправителя после подарка).
- `GET /api/v1/lives/{id}/gifts?after` — последние 50 или следующие после
  курсора; ведущему и допущенным зрителям, также после завершения.
- После commit всем в эфире уходит SSE `live`; клиенты дочитывают подарки.

## Web

- Иконка подарка в эфире у зрителя открывает вкладку: баланс с сервера,
  шесть подарков с ценой. Нажатие отправляет; при нехватке монет —
  «Недостаточно монет…» и ссылка «Получить монеты». Сетевая ошибка
  повторяется с тем же id, поэтому двойного списания нет.
- `GiftEffects` у ведущего и зрителей: подарки, пришедшие после открытия
  страницы, показываются строкой «… отправил(а) «Роза»»; тыква и кошка — на
  весь экран по очереди (~4 с). История до открытия страницы не проигрывается.
  После дорогого подарка вкладка закрывается, чтобы показ был виден.
