# Пересылка публикаций, Reels и историй

Срез от 2026-10-24: кнопка «Поделиться» в ленте, карточке публикации, Reels и
просмотре истории отправляет ссылку-карточку оригинала в личный Direct.
Можно выбрать существующий диалог либо найти пользователя и открыть диалог по
прежним правилам FR-09. Вложение не копируется в файлы Direct.

## Счётчик

`shareCount` — число уникальных существующих аккаунтов, отправивших оригинал
хотя бы раз через этот API. Повтор в другой диалог или с новым clientMessageId
создаёт новое сообщение, но этот аккаунт учитывается один раз за всё время
существования оригинала. У видеопоста и его Reels один общий счётчик. Автор
тоже может поделиться своим материалом и учитывается как один аккаунт.

Нажатие кнопки, открытие диалога, копирование ссылки, ошибка и откат транзакции
счётчик не увеличивают. Отследить доставку скопированной ссылки во внешнем сервисе
невозможно, поэтому «Копировать ссылку» явно сообщает, что счётчик не изменён.
Новые строки до первой пересылки имеют 0. Список отправителей и получателей
не публикуется. Изменение другим пользователем видно при следующем чтении API;
общего realtime-канала аналитики этот срез не добавляет. Компоненты одной страницы
синхронизируют успешную собственную отправку через локальное событие.

## API и общие схемы

`POST /api/v1/direct/conversations/{id}/messages/share`

```json
{
  "clientMessageId": "00000000-0000-4000-8000-000000000001",
  "kind": "post",
  "contentId": "00000000-0000-4000-8000-000000000002",
  "text": ""
}
```

kind: `post`, `reel`, `story`; text необязателен, максимум 1000 code points.
Неизвестные поля (включая URL, senderId и shareCount) отклоняются. Фото под видом
Reels не принимается. Ответ: 201 `{ message: DirectMessage, shareCount: number | null }`.
Общие request/response-схемы и endpoint в `@instagram/contracts`, Swagger обновлён.
Post и Story возвращают shareCount; optional в общей схеме позволяет принимать
прежние fixtures/ответы без поля. Реальный API выдаёт поле всегда.

`DirectMessage.sharedContent` — null либо:

- available: `{ status, kind, id, author, caption, thumbnailUrl, href, expiresAt }`;
- unavailable: **только** `{ status: "unavailable", kind }`.

Посты/Reels открываются по `/p/{id}`, истории по `/stories/{id}`. Для публикаций
expiresAt=null; для истории — исходное время истечения. Старые сообщения и
отправка текста, фото/GIF и голоса сохраняются без изменений.

## Доступ и приватность

Требуются действующая сессия и Origin/CSRF. Лимит общий с Direct:
60 отправок в минуту на аккаунт. Посторонний участникам диалог не видит (404).
Отправитель должен видеть оригинал сейчас. Получателю без доступа можно передать
сам факт пересылки, но его история и inbox получают только unavailable, без
автора, подписи, идентификатора оригинала, href и адреса превью. Если позже он
получит доступ, последующее чтение сможет показать карточку.

SharedContentService пакетно выбирает оригиналы с existing visiblePost /
visibleStory для **текущего читателя** при каждом чтении истории, inbox и ответов.
Публичность профиля не делает диалоги публичными; пересылка приватного поста
не выдаёт разрешение подписчика. Файлы и при открытии проверяются прежними
media-политиками, включая 24-часовое истечение истории. В БД нет скопированного
превью или подписи. После удаления оригинала ссылки FK обнуляются и сохраняется
нейтральная карточка. Срок жизни истории при пересылке не продлевается.

Ранее уже загруженный клиентом контент нельзя «развидеть»: при очередном REST sync
карточка обновляется, а новый запрос к закрытому/истёкшему файлу отклоняется сразу.
Пользовательский текст рядом с карточкой — явно отправленный текст Direct, а не
скрытая копия подписи источника. Все персональные ответы no-store; Next Image
optimizer не используется для приватных превью.

## Транзакция и повтор

DirectService владеет сценарием: проверка источника, создание сообщения, запись
уникального отправителя и lastActivityAt находятся в одной транзакции.
Идемпотентный ключ `(senderId, clientMessageId)` сравнивает диалог, kind,
contentId и текст. Конфликт, включая text/media ↔ share, — MESSAGE_ID_CONFLICT.
Пять конкурентных повторов дают одно сообщение и один учтённый аккаунт.
SSE после commit передаёт только id; карточка дочитывается обычной историей.

Повтор уже сохранённого запроса разрешён даже после удаления/истечения оригинала
или отзыва доступа: возвращает прежнее сообщение с unavailable и shareCount=null,
ничего не создаёт. Внутренний sharedTargetId остаётся для сравнения повтора и
не попадает в unavailable DTO. Новый запрос к такому источнику получает 404.

## UI

Небольшая кнопка Direct и число рядом с обычными действиями; в Reels/истории
компактное число. Окно выбора показывает поиск, явного получателя, состояния
loading/empty/error и ручной повтор. При потере ответа сохраняется тот же UUID
до повторной отправки тому же получателю. Повторный клик во время отправки
не запускает второй запрос. Закрытие/уход прерывают чтения и отправку.
История при открытом выборе приостанавливается; видео Reels останавливается.
Высота Reels на телефоне учитывает верхнюю и нижнюю панели и safe-area.

## Данные и миграция

`20261025030000_content_sharing` добавляет SharedContentKind, nullable-ссылки
сообщения на Post/Story с SET NULL, неизменяемый target id для повторов и CHECK
допустимого содержимого. Таблицы post_shares / story_shares имеют составной PK
оригинал+аккаунт и индексы аккаунта. Это журнал пересылок Direct; Posts/Stories
читают количество связей, без независимого инкрементируемого числа.
Удаление источника или аккаунта каскадно удаляет соответствующие строки журнала;
продуктовая политика удаления/анонимизации аккаунта остаётся отдельной задачей.

Применить миграцию к dev/test, а при деплое — к production до запуска нового API.
Ранее применённые SQL-файлы не менялись. Fresh deploy, redeploy и Prisma drift
проверены; upgrade заполненной изолированной БД сохраняет прежние поля, включая
старое текстовое сообщение Direct, и контрольные суммы старых миграций.

## Проверки

- Contracts/unit: строгий payload, unavailable без приватных полей, диалог/поиск,
  повтор с тем же UUID, двойной клик, копирование без счётчика, refetch счётчика,
  отсутствие старых результатов при ошибке нового поиска.
- PostgreSQL: положительная пересылка, уникальные аккаунты и Reels/post counter,
  конкурентные повторы, conflicts, приватный адресат, отзыв доступа, истечение
  истории, удаление, недопустимый payload/CSRF/участник, откат сообщения+журнала.
- Browser desktop/mobile: реальное фото и FFmpeg-видео, карточки всех трёх типов
  у второго пользователя, потеря ответа и retry без дубля, счётчик после reload,
  пауза истории при открытом выборе, отсутствие горизонтального overflow.
