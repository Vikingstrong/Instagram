# Direct: сохранение и история (этап 6)

FR-09 через REST: личные диалоги, отправка и чтение истории без
дубликатов — backend и frontend. Доставка без обновления страницы (SSE) —
этап 7. Решения приняты Developer 2 соло 2026-10-23, пока Developer 1
недоступен; требуют review в PR.

## Решения

| Вопрос | Решение |
| --- | --- |
| Кто может писать | Любой подтверждённый пользователь любому подтверждённому, независимо от подписки и приватности (FR-09). Себе — нельзя (`400 CANNOT_MESSAGE_SELF`) |
| P-07 блокировки и незнакомцы | Не реализуются в этом этапе и остаются открытым вопросом; FR-09 разрешение сохраняется |
| Диалог | Только на двоих; пара хранится упорядоченно (`userAId < userBId`, CHECK) с уникальным ключом — гонки «открыть» с обеих сторон дают один диалог |
| Пустой диалог | Виден в списке только тому, кто его открыл, пока нет сообщений — открытие не «уведомляет» собеседника |
| P-09 сообщение | 1–1000 code points, переводы строк разрешены, только пробелы — нельзя (Zod и CHECK в БД). Только текст |
| Повторы | Клиент создаёт `clientMessageId` (UUID) один раз и повторяет его при каждом retry. Уникальный ключ `(senderId, clientMessageId)`: повтор с тем же текстом возвращает сохранённое сообщение, другой текст или другой диалог — `409 MESSAGE_ID_CONFLICT` |
| Атомарность | Сообщение и `lastActivityAt` диалога сохраняются в одной транзакции; активность не откатывается назад при обгоне |
| Доступ | Только участники; остальным — `404 CONVERSATION_NOT_FOUND`, существование диалога не подтверждается. Текст сообщений не пишется в логи |
| Порядок | Список — `lastActivityAt DESC, id DESC`; история — `createdAt DESC, id DESC`, курсор читает более старые |
| Лимиты | Открытие диалогов 30 / час, сообщения 60 / мин на пользователя |
| Коды ответов | Открытие всегда `200`, отправка всегда `201` (в том числе повтор) — веб-клиент проверяет один успешный статус |

Известное ограничение: при новых сообщениях во время листания списка
диалогов порядок меняется, поэтому диалог может встретиться на двух
страницах; клиент объединяет по `id`. Подписка и синхронизация — этап 7.

## База

`20261023150000_direct`: `direct_conversations` (уникальная пара, CHECK
порядка пары и того, что создатель — участник; индексы по участнику и
`lastActivityAt`), `direct_messages` (уникальный `senderId, clientMessageId`,
CHECK непустого текста, индекс истории). Удаление пользователя каскадно
удаляет его диалоги и сообщения.

## Запросы

Все требуют подтверждённую сессию; мутации — Origin + CSRF.

| Метод | Путь | Ответ |
| --- | --- | --- |
| GET | `/api/v1/direct/conversations` | `{ items: Conversation[], nextCursor }` |
| POST | `/api/v1/direct/conversations` | `{ conversation }`; тело `{ userId }` |
| GET | `/api/v1/direct/conversations/{id}` | `{ conversation }` |
| GET | `/api/v1/direct/conversations/{id}/messages` | `{ items: DirectMessage[], nextCursor }`, новые сверху |
| POST | `/api/v1/direct/conversations/{id}/messages` | `201 { message }`; тело `{ clientMessageId, text }` |

`Conversation`: `id, peer (UserSummary), lastMessage | null, lastActivityAt`.
`DirectMessage`: `id, conversationId, senderId, clientMessageId, text,
createdAt`.

## Frontend

- `/direct` — список диалогов (собеседник, «Вы: …» для своих сообщений,
  время); на широком экране рядом заглушка «Ваши сообщения».
- `/direct/t/{id}` — диалог: на широком экране список слева, на телефоне
  только чат с кнопкой «Назад».
- Профиль другого пользователя — кнопка «Написать» открывает диалог.
- Отправка: поле очищается сразу, сообщение показывается как «Отправка…»;
  при ошибке — «Не отправлено», «Повторить» (тот же `clientMessageId`) и
  «Удалить». История и подтверждённые отправки объединяются по `id`, поэтому
  ни «Обновить», ни повтор не создают дубликатов.
- Новые сообщения собеседника приходят через SSE (этап 7, см.
  [Direct realtime](direct-realtime.md)); кнопка «Обновить» убрана.
- Плавающая кнопка «Сообщения» скрыта внутри Direct.
