# Фото, GIF и голосовые сообщения в Direct

Срез от 2026-10-24 расширяет FR-09: одно вложение с устройства на сообщение,
необязательная подпись до 1000 code points, запись голоса через MediaRecorder.
Право переписки прежнее: два подтверждённых пользователя, независимо от подписки
и приватности профиля. Новые сервисы и зависимости не добавлены.

## API

Все пути ниже начинаются с `/api/v1/direct/conversations/{id}`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/messages/image` | Multipart: `file`, `clientMessageId` UUID, необязательный `text`; ответ 201 `{ message }` |
| POST | `/messages/voice` | Те же поля; аудио проверяется и перекодируется на сервере; ответ 201 |
| GET | `/messages/{messageId}/{variant}` | `full` / `thumb` для фото, `audio` для AAC/M4A, `opus` для Opus/WebM; 200/206/416 |

Прежний JSON `POST /messages` сохраняет обязательный непустой текст и прежние
коды/лимиты. Общие схемы и endpoints — `@instagram/contracts`; Swagger содержит
multipart-поля, типы ответов и способы защищённого чтения.

`DirectMessage.attachment` — `null` или:

- `{ type: "image", url, thumbnailUrl, width, height }`;
- `{ type: "voice", url, opusUrl, durationMs }`.

Принимаются прежние ответы без attachment; opusUrl необязателен в схеме для
совместимости, сервер выдаёт обе версии. Пустой текст без attachment недопустим.
Ни mediaId, ни sourceHash, ни пути файлов в DTO не попадают.

## Обработка и лимиты

- Фото: JPEG, PNG, статический WebP, GIF до 10 MiB / 100 кадров / 40 млн пикселей
  суммарно. Sharp декодирует реальное содержимое, удаляет метаданные и создаёт
  WebP до 1080×1080 и статическую миниатюру. GIF сохраняет анимацию.
- Голос: до 10 MiB / 180 секунд. Входные контейнеры WebM, MP4/M4A, Ogg, WAV,
  MP3; проверяется наличие аудио и отсутствие видеопотока, MIME и расширение
  клиента не определяют допустимость. FFmpeg декодирует ограниченный по длине
  PCM mono 16 kHz, длительность считается по сэмплам. WebM MediaRecorder без
  заголовка длительности поддерживается. Превышение лимита отклоняется, а не
  незаметно обрезается. Выход — AAC/M4A и Opus/WebM без исходных метаданных.
- FFmpeg запускается без shell, с whitelist контейнеров/протоколов, ограничением
  stdout/stderr и 30 секундами на вызов. Один encoder и максимум четыре ожидающих
  загрузки; при перегрузке 503 SERVICE_UNAVAILABLE / Retry-After: 2. Временные
  файлы удаляются в finally, shutdown ждёт обработки аудио.
- Лимит отправки общий с текстом: 60 сообщений в минуту на пользователя.
  Добавлены INVALID_AUDIO (400), AUDIO_TOO_LONG (400), AUDIO_TOO_LARGE (413).

## Доступ, атомарность и повторы

Origin/CSRF и действующая сессия проверяются до разбора multipart; участник
проверяется до обработки файла. При каждом чтении, включая Range, DirectService
проверяет участие в текущем диалоге, принадлежность сообщения этому диалогу и
READY media правильного типа. Другие пользователи получают 404; гость — 401.
Общий `/media/{id}` не выдаёт DIRECT-вложения. Ответы no-store; фотографии
используют MediaImage, аудио — native audio/source; общий Next Image cache
не используется. Это приватность на сервере, не сквозное шифрование.

Клиент сохраняет исходный File и clientMessageId в памяти до успеха или удаления
неотправленного. Повтор сравнивает диалог, текст, тип вложения и SHA-256 исходных
байтов. Любое отличие — MESSAGE_ID_CONFLICT, включая смену text ↔ attachment.
При гонке unique(senderId, clientMessageId) оставляет одно сообщение; файлы
проигравшей загрузки удаляются. Повтор не выпускает повторное SSE-уведомление.

Активация media, сообщение и lastActivityAt фиксируются одной транзакцией.
Уведомление SSE (только id диалога и сообщения) идёт после commit; ошибка
уведомления не удаляет уже сохранённый файл. После разрыва клиент дочитывает
обычную историю через REST. Незавершённые загрузки подбирает MediaService.
После удаления диалога выдача закрывается сразу; READY DIRECT media без сообщения
помечаются DELETED и очищаются общим cleanup. Пользовательского удаления диалогов
этот срез не добавляет; политика полного удаления аккаунта остаётся отдельной.

## Интерфейс и микрофон

Высота чата на телефоне учитывает верхнюю панель 3.5rem, нижнюю навигацию
3rem и safe-area; прокручивается история, форма не перекрывается навигацией.
Под полем — «Фото / GIF» и «Записать голосовое», без emoji и крупных декоративных
иконок. Фото/GIF имеет превью и удаление до отправки; голос — прослушивание записи,
удаление и явную отправку. Запись не стартует без нажатия; HTTPS (или localhost)
и разрешение микрофона обязательны. Поддержка определяется MediaRecorder.
Видны таймер, «Остановить» и «Отменить запись»; автозавершение немного раньше
трёх минут оставляет запас на финальный chunk. При отказе разрешения есть ошибка
и повтор. Tracks и таймеры освобождаются при отмене, ошибке, уходе со страницы и
позднем разрешении после размонтирования.

В исходящих — состояние отправки и ручной повтор с тем же файлом/id; автоматической
повторной публикации нет. При смене аккаунта чат перемонтируется, запросы отправки
прерываются; неотправленные файлы не сохраняются на диск и теряются при reload.
Входящие обновляются существующим SSE; список диалогов показывает «Фото / GIF»
или «Голосовое сообщение» при отсутствии подписи. При уходе из чата, замене превью и смене аккаунта аудиоплеер явно останавливается
и освобождает запросы к источникам; старый звук не продолжает играть.
Аудиоплеер выбирает Opus/WebM
либо AAC/M4A в зависимости от поддержки браузера и позволяет перемотку.

## Миграции и проверки

Применить до запуска API (к dev/test, при деплое к production):

1. `20261025020000_direct_attachments`: MediaKind.DIRECT, MediaType.AUDIO,
   nullable mediaId/sourceHash, unique/FK, текст либо вложение.
2. `20261025021000_voice_media_state`: READY AUDIO требует измеренную длительность;
   READY image/video сохраняют положительные размеры.
3. `20261025022000_voice_media_invariants`: совместимость video CHECK с AUDIO;
   аватар и COMMENT остаются image, AUDIO разрешено только для DIRECT.

Миграции добавочные; старые строки сообщений не меняются. Срез использует общую
обработку изображений из PR с вложениями комментариев и должен сливаться после
него. Поиск GIF через внешний каталог и расшифровка голоса в текст не входят.

Проверки описываются по фактическому прогону в PR: общие contracts/unit, typecheck,
lint/build; PostgreSQL negative access, идемпотентность/гонки, Range, длительность,
очистка; браузерная отправка обоим участникам, потеря ответа и retry, запись через
настоящий MediaRecorder с fake microphone, воспроизведение и reload на desktop/mobile.
Физические микрофоны и Safari на реальном iPhone требуют отдельной проверки;
облачный Chromium с эмуляцией мобильного экрана её не заменяет.
