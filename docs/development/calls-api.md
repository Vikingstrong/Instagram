# Звонки 1:1 — FR-11 / этап 9

По указанию владельца от 2026-10-23: аудио и видео 1:1, свой микрофон и
камера, локальное отключение звука собеседника. WebRTC в браузере, REST и
существующий SSE для сигнализации, один NestJS процесс. CallsModule владеет
звонками; изменения активности диалога проводит DirectService.

## Поведение и безопасность

- Право звонить совпадает с текущим Direct: два подтверждённых участника
  существующего диалога, независимо от подписки и приватности. Блокировки
  P-07 не реализуются попутно. Посторонний получает 404 для звонка,
  сигналов и истории. Все мутации требуют Origin, CSRF и JSON.
- Один пользователь участвует только в одном незавершённом звонке.
  `call_seats.userId` — первичный ключ: обе занятости резервируются в одной
  транзакции; одновременные встречные вызовы дают один успех и один 409.
- Caller создаёт уникальный id, повтор с тем же id/данными возвращает
  сохранённый звонок. Принимает только callee, атомарно из RINGING.
  Принятие на другом устройстве после успешного принятия — 409.
- Сигналы и heartbeat привязаны к пользователю, хешу серверной сессии и
  UUID вкладки. UUID вкладки не является авторизацией. Cookie/хеши не
  возвращаются в DTO. offer передаёт caller, answer — callee, ICE — оба.
- Состояния: RINGING → ACTIVE → ENDED/FAILED; неотвеченный RINGING через
  45 с становится MISSED, отклонённый — DECLINED. Конкурентное завершение
  и принятие не возвращает завершённый звонок в ACTIVE.
- Heartbeat примерно раз в 6 с. Просрочка любой стороны на 20 с завершает
  ACTIVE как FAILED; проверка раз в 5 с. Logout/password reset завершают
  звонок по SessionRevocations. Истечение сессии прекращает heartbeat,
  затем освобождается занятость. Периодическая уборка проверяет lease
  повторно в UPDATE, чтобы не завершать уже обновлённый звонок.
- Клиент завершает звонок при отказе сигнализации, длительном отсутствии
  ответа API, failed, disconnected дольше 10 с или отсутствии соединения
  через 30 с после принятия. Треки останавливаются при завершении и уходе
  со страницы. Сворачивание экрана и переходы Next.js внутри приложения
  сохраняют звонок, provider расположен в корневом layout.
- Микрофон и камера переключают enabled собственных треков. Кнопка
  динамика меняет muted только у локального media-элемента. Она никогда
  не выключает микрофон собеседника. Камера доступна в видеорежиме.
- Входящий вызов не открывает устройства до нажатия «Принять». При отказе
  разрешений показывается понятная ошибка. Поздний результат getUserMedia
  после отмены сразу останавливается. Browser autoplay имеет ручную кнопку.

## Хранение и доставка

`20261023180000_direct_calls`: calls (участники, тип, состояние, времена,
серверные привязки сессий/вкладок) и call_seats. Миграция добавочная.
История доступна обоим участникам в диалоге; звонок появляется и в inbox
при отсутствии текстовых сообщений. Все ответы no-store.

SDP и ICE не пишутся в БД/логи/телеметрию: буфер в памяти на активный звонок,
не более 512 сигналов и 256 Ki символов JSON (с ограничениями длины отдельных
полей); при завершении удаляется. SSE `call` содержит только `{ callId }`.
Получатель догружает сигналы через REST с sequence cursor; потерянные
уведомления восстанавливаются polling раз в 1.5 с. После перезапуска API
несохранённая сигнализация недоступна: новый handshake требует нового
звонка; просроченные записи очищаются по lease. Несколько API-инстансов
для этого буфера не поддерживаются, как и существующий SSE hub.

Provider звонков открывает поток отдельно от Direct: максимум 5 потоков
на пользователя по прежнему правилу hub. Во многих вкладках вытеснение
потока компенсируется polling. Лимиты звонков отдельные от login/mail:
10 новых вызовов/мин, 400 мутаций/мин и 300 чтений/мин на пользователя,
5000 мутаций/5 мин на socket IP. CSRF endpoint сохраняет общий лимит:
на размещённом proxy требуется подобрать AUTH_READ_IP_LIMIT под нагрузку.

## REST

- GET `/api/v1/calls/config`: ICE-конфигурация подтверждённого пользователя.
- POST `/api/v1/calls`: `{ id, conversationId, kind: AUDIO|VIDEO, clientId }`.
- GET `/api/v1/calls/current`: `{ call: Call|null }`.
- GET `/api/v1/calls/{id}`: `{ call }`, включая завершённый.
- POST `/api/v1/calls/{id}/action`: `{ action: accept|decline|end|fail, clientId }`.
- POST `/api/v1/calls/{id}/heartbeat`: `{ clientId }` → `{ call }`.
- POST `/api/v1/calls/{id}/signals`: `{ clientId, signal }` → accepted.
- GET `/api/v1/calls/{id}/signals?clientId=...&after=0`: `{ items, next }`.
- GET `/api/v1/calls/history/{conversationId}`: курсорная история звонков.

Публичные схемы находятся в packages/contracts/src/calls.ts. Conversation
получает необязательное lastCall: старые fixtures без него остаются валидны.
Старые клиенты со strict-схемой Conversation нужно обновлять одновременно с API.
Новые ошибки: CALL_NOT_FOUND, CALL_BUSY, CALL_STATE_CONFLICT, CALLS_UNAVAILABLE.

## ICE / реальная сеть

Для localhost два браузера могут соединиться без внешних серверов. Для
удалённых сетей нужны настроенные STUN и TURN; локальный тест этого не
доказывает. Новые сервисы автоматически не устанавливаются.

Серверные настройки (примеры, только placeholders):

```dotenv
CALLS_STUN_URLS=stun:stun.example.test:3478
CALLS_TURN_URLS=turn:relay.example.test:3478,turns:relay.example.test:5349
CALLS_TURN_SECRET=<persistent-shared-secret-at-least-32-characters>
```

TURN должен поддерживать REST shared-secret authentication (например,
coturn в соответствующей конфигурации). API выдаёт временные credentials
сроком 1 час: timestamp:userId / HMAC-SHA1. Сам shared secret не поступает
в браузер. Длительные звонки с истёкшими TURN credentials отдельно не
проверены. В production отсутствие TURN закрывает config/start с 503,
чтобы не обещать связь без relay. Выбор провайдера, HTTPS и реальные
NAT/TURN проверки — отдельная приёмка перед deployment.

Ручной тест: обычное окно и инкогнито одного браузера дают независимые
cookie-сессии. Две обычные вкладки и device emulation этого не дают.
Войти разными подтверждёнными аккаунтами, разрешить устройства в каждом
окне и позвонить из Direct. Для теста настоящих устройств удобны наушники;
при занятости камеры другим приложением можно сначала проверить AUDIO.
