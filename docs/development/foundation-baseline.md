# FND-01 — Технический baseline и workflow

Схема локальных запросов и остальные пункты baseline согласованы владельцем
проекта 2026-10-21. Маршрутизация web и readiness smoke реализованы в
[FND-05](web-api.md). Отдельное review Developer 2 остаётся
условием закрытия FND-01 по roadmap.

## Версии и инструменты

- Node.js 24.19.0 (`.nvmrc`), pnpm 12.14.0 (корневой `packageManager`).
- PostgreSQL 18.6; Prisma CLI, Client и PostgreSQL adapter 7.10.1.
- Prisma: генератор `prisma-client`, ESM/NodeNext, `PrismaPg` из
  `@prisma/adapter-pg`. Схема, конфигурация и будущие миграции принадлежат API.
  Подробности: [Database Foundation](database.md).
- API: Vitest/Supertest; контракты: node:test; web: Vitest и Testing Library;
  browser runner: Playwright, desktop и mobile. Существующая конфигурация
  использует локальный Google Chrome (либо `PLAYWRIGHT_CHANNEL`), в CI —
  Chromium Playwright. Наличие конфигурации не подтверждает установку браузера
  или успешный запуск проверок.

## Локальные запросы и запуск

| Назначение | Адрес / правило |
| --- | --- |
| Web и внешний origin для браузера | `http://localhost:3000` |
| NestJS API | `http://localhost:4000` |
| REST из браузера | Относительный путь `/api/v1/*` на origin web; Next.js проксирует запрос в NestJS с сохранением пути |
| REST из Server Components | Прямой HTTP-запрос к NestJS; абсолютный внутренний адрес берётся из серверной конфигурации |

При появлении сессий серверный web передаёт контекст сессии в API; собственная
авторизация и доступ к БД в Next.js не создаются. API остаётся владельцем всех
прикладных операций. Внутренний адрес API не требует `NEXT_PUBLIC_*`.

Общий запуск приложений: `pnpm dev`; по отдельности: `pnpm dev:web` и
`pnpm dev:api`. Ожидаемые порты — 3000 и 4000, при локальном запуске API нельзя
переопределять `PORT` другим значением. PostgreSQL запускается отдельно по
[инструкции](database.md), с изолированными dev/test базами и ролями.

Readiness и Swagger реализованы в [FND-04](api-readiness.md).
Proxy и серверный клиент web реализованы в [FND-05](web-api.md);
внутренний адрес задаёт серверная переменная `API_INTERNAL_ORIGIN`.
Стартовый `GET /` сохранён отдельно и не проверяет БД.
Локальная схема не меняет deployment-архитектуру: общий HTTPS origin
маршрутизирует API и SSE непосредственно в NestJS. Production и SSE через
локальный proxy этим решением не считаются проверенными.

## Владение и проверки PR

Developer 1 отвечает за API, БД и инфраструктуру; Developer 2 — за web и
frontend-тесты. Developer 1 координирует контракты; оба согласуют схемы до
зависимой реализации. Root scripts, lockfile, миграции и общие контракты
изменяются согласованно. Один PR имеет одного владельца и требует человеческого
review; auth, политики доступа и миграции требуют внимания обоих разработчиков.

Проверки кода: `pnpm check-types`, `pnpm lint`, `pnpm test`, `pnpm test:e2e`
и `pnpm build`; реальные проверки PostgreSQL запускаются отдельно:
`pnpm --filter @instagram/api test:integration`. Детальный выбор зависит от
изменения. Root e2e включает API и Playwright web; отсутствующие или пропущенные
проверки не засчитываются как PASS. Workflow FND-07 описан в [Foundation CI](ci.md);
наличие конфигурации не подтверждает успешный GitHub run.

## Ожидаемый вертикальный smoke

Браузер открывает web на 3000 и запрашивает `/api/v1/readiness` через тот же
origin. Next.js передаёт запрос API на 4000; API проверяет настоящий PostgreSQL.
При доступной БД возвращается согласованный ответ 200, при недоступной —
безопасный конверт ошибки 503 без секретов. Ответ проходит общую Zod-схему;
fixture не заменяет БД. Сквозной smoke реализован в FND-04–FND-06; результаты web-интеграции
описаны в [FND-05](web-api.md). Совместная приёмка относится к FND-08. Наличие интерфейса и тестового harness этот результат не закрывает.

Локальная тестовая почта относится к FND-03; владелец проекта согласовал
Mailpit в существующем Docker Compose. Настройка описана в
[локальном окружении](local-environment.md).
Режим публичной регистрации и демонстрация настоящей доставки писем остаются
отдельными продуктовыми решениями.
