# FND-08 — Совместная приёмка Foundation

Статус: **не завершена**. Облачные проверки и CI не подтверждают запуск на
реальных ноутбуках обоих разработчиков. Владелец 2026-10-22 разрешил реализацию
этапа 2 до завершения FND-08. Этот чек-лист остаётся обязательным до окончательной
приёмки этапа 2; разрешение не закрывает ни одну неподтверждённую проверку.

## До начала работы на каждом реальном ПК

В отдельном чистом checkout одного согласованного commit SHA выполните
[локальную инструкцию](local-environment.md) и [инструкцию БД](database.md).
Не копируйте облачный `.env`, используйте собственные локальные пароли.
Зафиксируйте ОС, commit SHA, версии Node/pnpm и способ запуска PostgreSQL.

1. Выберите Node из `.nvmrc`, pnpm из `packageManager`; выполните
   `pnpm install --frozen-lockfile`. Настройте `.env` из `.env.example`, раздельные
   dev/test URL и роли. Секреты не включайте в отчёт.
2. Проверьте `docker compose config --quiet` и запустите
   `docker compose up -d --wait postgres` либо согласованный native
   PostgreSQL по инструкции. С 2026-10-24 Mailpit и подтверждение email удалены;
   проверить регистрацию → ленту без почтовых настроек. Recovery проверять отдельно
   только при явном включении; [инструкция Developer 2](auth-without-verification.md).
3. Выполните `pnpm build`, `pnpm check-types`, `pnpm lint`, `pnpm test`,
   `pnpm --filter @instagram/api db:validate`,
   `pnpm --filter @instagram/api db:migrate:deploy`,
   `pnpm --filter @instagram/api db:migrate:test`,
   `pnpm --filter @instagram/api test:integration`.
   Первая Auth-миграция создаёт пользователей, сессии и токены. Успешный deploy
   не означает готовность регистрации или восстановления пароля.
4. Запустите `pnpm dev` и откройте `http://localhost:3000`. Проверьте настоящий
   `GET /api/v1/readiness` через origin web и Swagger на
   `http://localhost:4000/api/docs/`. API и БД должны оставаться доступны для
   E2E. Выполните `pnpm test:e2e` в другом терминале; Playwright использует
   локальный Chrome либо явно выбранный установленный канал, см.
   [frontend testing](frontend-testing.md). Не запускайте одновременно другие
   команды генерации/сборки в этом checkout.
5. В изолированном локальном проекте проверьте отсутствие БД: readiness — `503`,
   безопасное тело и `Cache-Control: no-store`; после возвращения БД — `200`
   без перезапуска API. Не останавливайте общие/чужие контейнеры. Для общей
   dev-БД эту проверку пропустите с причиной и повторите в отдельном окружении.
6. Остановите только свои процессы. Данные сохраняйте; не используйте
   `docker compose down -v` для этой приёмки.

Если проверка упала, запишите ошибку без секретов, исправление и результат
повторного запуска. Отсутствующая команда, пропущенный тест или успешная
альтернативная сборка не заменяют обязательную проверку. Например, Webpack не
заменяет штатный `pnpm build` с Turbopack при ошибке загрузки шрифтов.

[run 39708648475](https://github.com/Vikingstrong/Instagram/actions/runs/39708648475).
Это историческое свидетельство для того commit, не проверка будущих изменений
и не приёмка двух ноутбуков. CI также не проверяет реальную публичную доставку
писем и ещё не реализованные Auth-сценарии.

FND-08 закрывается после заполнения реестра доказательствами, разбора ошибок
и совместной приёмки критериев [roadmap §6](../roadmap.md#6-критерии-перехода-ко-второму-этапу).
Одно лишь объединение PR не заменяет эту процедуру.
