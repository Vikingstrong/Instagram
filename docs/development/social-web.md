# Social web — профиль, подписки, рекомендации, поиск (этап 3)

Frontend этапа 3 поверх [Users API](users-api.md). Все страницы обёрнуты в
`HomeAccess` (проверка сессии, гостевой режим) и `AppShell`.

| Маршрут | Компонент | Что делает |
| --- | --- | --- |
| `/` | `SuggestionsProvider`, `SuggestionsCarousel`, `RightSidebar` | Рекомендации из `GET /me/suggestions?limit=20`: один запрос на страницу, общий статус подписки для карусели и сайдбара. Пустой список, ошибка или гость — блоки не показываются |
| `/[username]` | `ProfileView` | Шапка, счётчики, Follow/Requested/Following, «Редактировать профиль» для себя, «Это закрытый аккаунт», «страница недоступна» для 404 |
| `/accounts/edit` | `ProfileSettings` | username, имя, био, приватность; отправляются только изменённые поля, лимиты из контракта; после смены username — переход на новый адрес |
| `/notifications` | `FollowRequests` | Входящие запросы: подтвердить/удалить; уже обработанный (404) убирается из списка |
| `/search` | `UserSearch` | Поиск с задержкой 300 мс, trim, до 160 символов, «Показать ещё» |

Списки подписчиков/подписок открываются из счётчиков профиля
(`UserListDialog`); владелец может удалить подписчика. Для приватного профиля
без доступа счётчики не кликабельны.

## Правила

- Все запросы — через `lib/api/social.ts` (`createSocialClient`); мутации
  получают свежий CSRF и не повторяются автоматически.
- `FollowButton` не меняет состояние оптимистично: показывает ответ сервера.
- Данные зависят от аккаунта: `HomeAccess` пересоздаёт страницу при смене
  пользователя; при перепроверке сессии (`useHomeChecking`) профиль не
  сбрасывается.
- Пункт навигации «Профиль» ведёт на `/{username}` текущего пользователя.
- Постраничные списки — `usePagedList` (курсор, «Показать ещё», отмена
  устаревших ответов).
- Username, совпадающий со статическим маршрутом (`search`, `notifications`,
  `accounts`, `auth`), не имеет страницы профиля по этому адресу.

## Проверки

- `features/social/social.test.tsx` — рекомендации (общий статус, скрытие,
  гость), профиль (подписка, приватность, удаление подписчика, 404),
  настройки (только изменённые поля, валидация, смена username, 409), запросы
  (подтвердить/удалить/уже обработан), поиск (debounce, trim, страницы, пусто).
- `e2e/social.spec.mts` — UF-03 в браузере для двух пользователей на TEST-базе:
  приватность в настройках → поиск → запрос → подтверждение → доступ →
  отписка. Требует API на TEST-базе (`scripts/ci/start-test-api.mjs`).
