# Лента, лайки и комментарии (этап 5)

FR-05 и FR-06: хронологическая лента, лайки и комментарии — backend и
frontend. Решения приняты Developer 2 соло 2026-10-23, пока Developer 1
недоступен; требуют review в PR.

## Решения

| Вопрос | Решение |
| --- | --- |
| Состав ленты | Свои посты и посты одобренных подписок (FR-05); без рекомендаций. Остаётся в `PostsModule` |
| Порядок и курсор | `createdAt DESC, id DESC`, курсор `<время>~<id>`; одинаковое время различается по id, новые посты между страницами не дублируют старые |
| Доступ | Правило `post-policy.ts` — часть WHERE до `LIMIT`: отозванная подписка убирает посты сразу |
| Лайк | `PUT` ставит, `DELETE` снимает; оба повторяемы. Первичный ключ `(postId, userId)` — не больше одного лайка при любой гонке |
| P-09 комментарий | 1–2200 code points, переводы строк разрешены, только пробелы — нельзя (Zod и CHECK в БД) |
| Удаление комментария | Автор комментария или автор поста (FR-06). Остальные: `403 CANNOT_DELETE_COMMENT`, если видят пост, иначе `404 COMMENT_NOT_FOUND` |
| P-10 | Автор комментария может удалить свой комментарий и после потери доступа к посту; читать пост и комментарии он уже не может |
| Лимиты | Лайки 300 / 5 мин, комментарии 60 / 10 мин на пользователя |

## База

`20261023120000_likes_comments`: `post_likes` (PK `postId, userId`),
`comments` (`text` VARCHAR(2200), CHECK `text ~ '\S'`, индекс
`postId, createdAt, id`), индекс ленты `posts (createdAt DESC, id DESC)`.
Удаление поста или пользователя каскадно удаляет его лайки и комментарии.

## Запросы

Все требуют подтверждённую сессию; мутации — Origin + CSRF, тело `{}` там,
где данных нет. Скрытый пост для любого действия — `404 POST_NOT_FOUND`.

| Метод | Путь | Ответ |
| --- | --- | --- |
| GET | `/api/v1/feed` | `{ items: Post[], nextCursor }` |
| PUT / DELETE | `/api/v1/posts/{id}/like` | `{ liked, likeCount }` |
| GET | `/api/v1/posts/{id}/comments` | `{ items: Comment[], nextCursor }`, старые сверху |
| POST | `/api/v1/posts/{id}/comments` | `201 { comment }`; тело `{ text }` |
| DELETE | `/api/v1/comments/{id}` | `{ status: "deleted" }` |

`Post` теперь содержит `likeCount`, `commentCount` и `liked` (лайк зрителя);
`Comment` — `id, postId, author, text, createdAt, canDelete`.

## Frontend

- Главная: вошедший видит настоящую ленту (`features/posts/feed.tsx`),
  «Показать ещё», пустое состояние со ссылками на поиск и публикацию. Гость
  по `?guest=1` по-прежнему видит макет, где действия просят войти.
  Короткая перепроверка сессии не сбрасывает загруженную ленту.
- Лайк (`like-button.tsx`): сердце и счётчик меняются сразу, затем берутся
  из ответа сервера; при отказе — откат и сообщение. Один запрос за раз.
- Комментарий: Enter отправляет, Shift+Enter — новая строка; пустой
  отправить нельзя, при ошибке текст остаётся в поле.
- Страница поста: лайк, счётчик, список комментариев с «Показать ещё» и
  удалением с подтверждением (кнопка только при `canDelete`). Свой новый
  комментарий не дублируется, когда позже приходит страница с ним.
