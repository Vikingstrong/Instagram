# Users API — профиль (этап 3, первый срез)

Первый срез этапа 3: база отношений и текстовый профиль. Подписки, поиск и
списки — следующие срезы. Решения приняты Developer 2 соло 2026-10-22, пока
Developer 1 недоступен; требуют review в PR.

## Решения по продуктовым блокерам

| ID | Решение |
| --- | --- |
| P-04 | Профили и поиск доступны только подтверждённой сессии; гостевого чтения профилей нет |
| P-05 | Списки подписчиков/подписок приватного профиля видят владелец и одобренные подписчики; счётчики видны всем |
| P-06 | Публичный → приватный: подписчики сохраняются. Приватный → публичный: все ожидающие запросы одобряются в той же транзакции |
| P-07 | Блокировки не входят в этап 3 |
| P-09 | `displayName` ≤ 30, `bio` ≤ 150 code points (bio допускает перевод строки, управляющие символы запрещены); поисковый запрос ≤ 160; страница 20, максимум 50 |

## База

Миграция `20261022130000_users_profile_follows`:

- `auth_users`: `displayName VARCHAR(30)`, `bio VARCHAR(150)` (по умолчанию
  пустые), `isPrivate BOOLEAN` (по умолчанию `false`).
- `follows`: PK `(followerId, followeeId)`, `status` `PENDING | ACCEPTED`,
  `acceptedAt`. CHECK запрещает подписку на себя и требует
  `acceptedAt` ровно для `ACCEPTED`. Каскадное удаление с пользователем.
  Индексы `(followeeId, status)` и `(followerId, status)`.

## Запросы

Контракт — `packages/contracts/src/users.ts`. Все маршруты требуют
подтверждённую сессию (`401 AUTHENTICATION_REQUIRED`,
`403 EMAIL_VERIFICATION_REQUIRED`), отвечают `Cache-Control: no-store` и
используют общий конверт ошибок Auth.

| Метод | Путь | Ответ / ошибки |
| --- | --- | --- |
| GET | `/api/v1/users/{username}` | `{ profile }`: id, username, displayName, bio, `avatarUrl: null`, isPrivate, `counts` (posts пока 0; только одобренные подписки), `relationship` `self/none/requested/following`. Username без учёта регистра. `404 USER_NOT_FOUND` для неизвестных и неподтверждённых, `400` для некорректного имени |
| GET | `/api/v1/me/profile` | `{ profile }`: id, username, displayName, bio, isPrivate |
| PATCH | `/api/v1/me/profile` | Частичное изменение (минимум одно поле), Origin + CSRF. `409 USERNAME_TAKEN` без учёта регистра; `400` для неверных полей |

Сводка приватного профиля содержит те же поля, что и публичного (FR-02);
публикации будут выдаваться отдельными маршрутами с проверкой доступа.
Будущий запрос подписки обязан читать `isPrivate` под той же блокировкой
строки пользователя (`FOR UPDATE`/`FOR SHARE`), что и смена приватности.
