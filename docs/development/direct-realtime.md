# Direct: realtime и восстановление (этап 7)

Завершение FR-09: новые сообщения появляются без обновления страницы,
пропущенные догружаются после разрыва. Решения приняты Developer 2 соло
2026-10-23, пока Developer 1 недоступен; требуют review в PR.

## Решения

| Вопрос | Решение |
| --- | --- |
| Транспорт | Server-Sent Events: `GET /api/v1/direct/events`, cookie-сессия и подтверждённый email проверяются до открытия потока; токен в URL не передаётся |
| Содержимое событий | `ready` — подписка активна; `message` — `{ conversationId, messageId }` после commit; комментарий `: ping` — heartbeat. Текст сообщений по потоку не идёт, только через REST-историю |
| Источник истины | PostgreSQL. Событие — подсказка «есть новое»; потерянное событие исправляется синхронизацией |
| Порядок подключения | Подписка → `ready` → REST-синхронизация, поэтому сообщения между загрузкой истории и подпиской не теряются |
| Синхронизация | Читает новые страницы истории, пока не встретит уже известное сообщение (до 10 страниц), объединяет по `id`. Запускается на `ready` (в т. ч. после переподключения), на событие открытого диалога, при возврате во вкладку, `online` и раз в 30 с |
| Кому событие | Обоим участникам, включая другие вкладки отправителя. Повтор с тем же `clientMessageId` нового события не создаёт |
| Конец потока | Logout и сброс пароля закрывают потоки сразу (внутренний сигнал `SessionRevocations`); любой другой отзыв или истечение сессии — на ближайшем heartbeat (20 с), который перепроверяет сессию |
| Ресурсы | Не больше 5 потоков на пользователя (новый закрывает самый старый); клиент, у которого в буфере больше 64 КБ непрочитанного, отключается; лимит открытий 60 / мин |
| Прокси | `Cache-Control: no-cache, no-store, no-transform`, `X-Accel-Buffering: no`, сокет без таймаута; проверено через rewrite Next.js |
| Масштаб | Один процесс API (архитектура §5): хаб в памяти, без Redis. Несколько инстансов потребуют брокера — не в этой итерации |
| Переподключение | Браузер сам переподключает `EventSource` (`retry: 3000`); если поток закрыт окончательно (например, 401), клиент открывает новый с backoff до 30 с |
| UI | Индикатор в шапке диалога: «В сети», «Подключение…», «Нет соединения. Переподключаемся…». Кнопка «Обновить» этапа 6 убрана |

Индикаторы прочтения и набора текста не входят в обязательный объём.

## Проверки

- `apps/api/src/direct/direct-events.spec.ts` — `ready` первым, события
  только участникам, лимит потоков, отключение медленного клиента, отзыв по
  токену и по пользователю, heartbeat и закрытие после неудачной проверки
  сессии.
- `apps/api/test/direct-events.integration-spec.ts` (настоящий HTTP) — 401 и
  403 до открытия, заголовки, `ready` и heartbeat; события обоим участникам
  и никому больше, только id, без события на повтор; logout закрывает
  поток, новый поток после logout — 401; отзыв сессии в БД закрывает поток
  на heartbeat.
- `apps/web/features/direct/realtime.test.tsx` — синхронизация только после
  `ready`, события, возврат во вкладку, переподключение с backoff,
  закрытие разрыва в 45 сообщений за три страницы без дубликатов,
  индикатор соединения.
- `apps/web/e2e/direct.spec.mts` (desktop и mobile) — сообщения в обе
  стороны без обновления страницы; обрыв (поток вытеснен, переподключение
  заблокировано), сообщения в это время, после восстановления — догружены
  все, без дубликатов; посторонний не видит диалог.
