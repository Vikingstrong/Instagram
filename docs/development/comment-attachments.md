# Фото и GIF в комментариях

Реализовано 2026-10-24: одно вложение из файла устройства в корневом комментарии
или ответе. Текст необязателен только при наличии вложения. Обычные текстовые
комментарии сохраняют прежний JSON API и ограничение 1–2200 символов.

## API и хранение

`POST /api/v1/posts/{id}/comments/image` — multipart: обязательный `image`,
необязательные `text` и `replyToCommentId`; ответ 201 `{ comment }`.
В Swagger описаны поля и лимиты. Общие схемы находятся в `@instagram/contracts`.
`comment.attachment` — объект `{ url, thumbnailUrl, width, height }` или `null`;
для совместимости прежние объекты без этого поля тоже принимаются клиентом.

JPEG, PNG, статический WebP и GIF: до 10 MiB, до 100 кадров и до 40 млн пикселей
суммарно по кадрам. Имя и MIME клиента не определяют допустимость: Sharp
декодирует содержимое и повторно кодирует его без исходных метаданных.
Анимированный GIF преобразуется в анимированный WebP; thumbnail статический.
Выходной размер до 1080×1080, без увеличения. SVG, повреждённые файлы,
анимированный WebP и превышение лимитов отклоняются.

Используется существующий MediaModule с приватным файловым хранилищем, без
внешних GIF-каталогов и новых сервисов. Создание комментария и активация media
атомарны; при отказе файлы отбрасываются, незавершённые загрузки подбирает cleanup.
После удаления комментария, ветки или публикации файл сразу перестаёт выдаваться;
периодическая очистка удаляет оставшиеся COMMENT media без владельца-комментария.

Все операции требуют подтверждённой сессии; загрузка также проверяет Origin и CSRF
до разбора файла. Лимит отправки общий с текстовыми комментариями: 60 за 5 минут.
Каждое чтение full/thumb проверяет текущий доступ к публикации. Защищённые файлы
отображаются через MediaImage, без общего кеша Next Image.

## Интерфейс

Под полем комментария — «Фото / GIF»: выбор, превью и удаление перед отправкой.
Во время отправки поля блокируются; при ошибке текст и файл сохраняются для
ручного повтора. Автоматического повтора публикации нет. Blob URL освобождаются
при замене, очистке и размонтировании формы. Поиск GIF через сторонний каталог
в этот срез не входит.

## Миграция и проверка

До запуска обновлённого API применить миграцию `20261025010000_comment_attachments`
и `20261025011000_comment_attachment_content`
к dev/test и затем при деплое к production обычным процессом миграций проекта.
Первая добавляет MediaKind.COMMENT и nullable unique comments.mediaId с FK;
вторая разрешает пустой текст только при наличии вложения.
Существующие комментарии и файлы не меняются.

Проверки: общий typecheck/lint/build; unit-тест формы multipart с отказом и повтором;
реальный PostgreSQL integration (анимация из двух кадров, приватность, CSRF,
недопустимые файлы, ответ, удаление ветки и cleanup); браузерный сценарий
создания вложения, перезагрузки страницы и удаления публикации.


Проверено в облачной среде: 210 unit/contract, 132 интеграционных теста с
PostgreSQL и 4 API E2E/OpenAPI; typecheck, lint и build проходят. В ходе проверки
исправлено старое ограничение comments_text_not_blank, запрещавшее комментарий
без текста даже с вложением. Проверки на физических устройствах разработчиков
по FND-08 остаются отдельной приёмкой.

Браузерный прогон: 40 passed, 2 ожидаемых пропуска по viewport; сценарий фото
и GIF в комментариях проходит на desktop и мобильном размере экрана.
